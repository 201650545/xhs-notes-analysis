## 一、今日最重要的结论：旧链路证伪，新链路跑通

### 1. 旧批次（raw_20260922，#89~#118）核查结论：30 条全部不可信

| 核查项 | 结果 |

**根因**：旧脚本走的是 `/ai_chat` 独立对话页粘贴外链。点点在该页面无法读取小红书外链内容，只会输出兜底话术或无关内容，脚本误把无关内容当总结存盘。**这批数据作废，不可用于报告或飞书。**

### 2. 正确链路（今日跑通并验证）

入口不在 `/ai_chat`，而在**首页搜索框内的「问点点」按钮**：

```
1. 打开 https://www.xiaohongshu.com/explore
2. click   button.wendian-btn                 ← 搜索框原地展开为点点提问面板
3. fill    #search-input-in-feeds             ← 提示词 + 笔记链接
4. 派发 Enter 键盘事件（keydown/keypress/keyup） ← 唯一有效发送方式
5. 页面跳转 /ai_chat_tab?conversationId=…
6. 轮询 .ai-message，等到 class 含 ai-message-finished
7. 提取 .ai-message innerText
```

**三个关键坑（全部实测确认）**：
1. **点 ↑ 发送按钮无效**：`.bottom-box-right-submit-button` 点击返回 success 但不触发任何动作；**只有回车有效**。
2. **输入框有真假两个**：真身是 `#search-input-in-feeds`；旁边还有一个 `aria-hidden` 的同名 textarea 是干扰项。
3. **面板会自动收起**：点击「问点点」后若停留不操作，面板会收回，所以点击→输入→回车必须在一次运行内连续完成。

**有效性验证**：《樱花草｜D调简谱》一次通过，点点准确输出曲目、1=D 调式、数字简谱记法、歌词节选、话题标签，与笔记内容完全一致（571 字）。

### 4. 下午进展：笔记卡片机制 + 链路二次突破（18:00 更新）

#### (1) 发现「笔记卡片」——纯文本链接不稳的真正原因

在问点点输入框中**真实粘贴**小红书链接时，前端会识别链接、拉取笔记元数据，把链接转成一张结构化笔记卡片：

```
.xhs-ai-selected-notes
 └─ .xhs-ai-selected-note-card
     ├─ img.xhs-ai-selected-note-cover     封面缩略图
     ├─ .xhs-ai-selected-note-title        笔记标题
     ├─ .xhs-ai-selected-note-sub          视频·N天前
     └─ button.xhs-ai-selected-note-remove × 删除
```

链接文本随即从输入框消失，笔记以**附件实体**（带 note_id）随提问一起提交——这才是点点稳定读懂笔记的方式。程序 `fill` 只改 value、合成 paste 事件 isTrusted=false，都无法触发识别。

#### (2) 最终方案：CDP 物理键盘 Ctrl+V

| 尝试 | 结果 |
|---|---|
| `fill` / `key_type` 输入链接 | 文字进框，组件不识别，不出卡片 |
| JS 合成 ClipboardEvent('paste') | isTrusted=false，被组件拦截 |
| 守护进程 send_keys 发 OS 级 Ctrl+V | 小红书 tab 在后台窗口，键事件送不到 |
| **CDP `Input.dispatchKeyEvent` 发 Ctrl+V** | ✅ 浏览器视为真实粘贴，1 秒出卡片 |

要点：链接写入系统剪贴板 → `Page.bringToFront` 开焦点模拟（不抢用户当前窗口焦点）→ CDP 派发 Control↓/V↓/V↑/Control↑ 物理序列。
