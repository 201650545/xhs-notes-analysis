# 笔记筛选规范（长期执行策略）

> **本文件是策略，不是参考资料。** 任何 Agent 遇到"筛选/处理/审判笔记"类意图，必须先读本文件再动手。
> 建立：2026-09-28，由多轮真实判例归纳；判例持续累积，新判例与本规范冲突时，以用户最新判决为准并回写本文件。
> 根目录 `AGENTS.md` 是跨 Agent 入口，本文件是细则。

## 0. 触发条件（自动识别）

用户说"筛选笔记 / 处理笔记 / 继续 / 再来一局 / 一审、二审 / 这篇删 / 这篇留 / 帮我全部审一遍"等，
即进入本规范。不需要用户重复规则。

## 1. 分工与边界（2026-10-11 郭老师重构为三级）

**旧制**：助手一审预判 → 用户二审终审。
**新制（郭老师 2026-10-11 定）**：同一套规则（本文件 §4）之下——
1. **模型一做一审**：分组读全文，按 §4 逐篇出 verdict+理由（子代理分组，fresh 非 fork）
2. **模型二做二审**：不同的模型（经本地网关 :3100 换另一条线）拿同一批材料+§4 独立重判
3. **冲突才上三审**：两个 AI verdict 不一致的篇目才交给郭老师；他只看争议篇，
   其余按一致结论走。用户已用 50 篇真实判定完成口味校准（台账 `_系统数据/text_review_verdicts.jsonl`）

- 一致结论的批次执行前仍须 dry-run 预览（四处同步真删不可逆，铁律不变）
- 会过时的保留信息打时效标签，由任务 C 到期复核（见 §4 时效分级）
- 用户会持续用三审判例校准；被改判的规则必须回写 §4
- 一审阶段绝不修改任何数据；只有拿到判决才执行删除/保留

## 2. 工作模式

**模式 A：逐局深聊（默认，5 篇/局）**
1. 从 `_系统数据/_routing.json` 取未保留且未标记 `已呈现` 的条目，随机抽 5（ID 以 JSON 键为准，先写临时文件再读，勿手抄终端输出——会丢字符）
2. 台账标记 `已呈现: true` + `呈现日期`
3. 逐篇讲透并给预判
4. 用户判决 → 立即四处同步 → 问是否开下一局

**模式 B：批量一审 + 集中二审**
1. 可对全部待判笔记批量出一审（子代理分组读全文，助手复核改判后汇总）
2. 产出一审文件到本目录（`一审预判vN_日期.md`）：速览表（含空白"二审判"列）+ 详述 + 争议项置顶
3. 用户集中二审后，按判决统一执行

### 2.1 二审的两种方式

- **口头式**：用户直接回复“全按你”“12删 13留”，助手据此执行（小批次适用）
- **判决台式**（批次较大时）：一审同时产出结构化批次文件 `_系统数据/review_batch_<批次>.tsv`（列：id/title/category/suggestion「keep|drop|dispute」/reason「判决理由」/what「讲什么」/use「有什么用」/fulltext；旧批次无 what/use 也兼容），由 `scripts/build_review_ui.py --input … --output …/二审判决台.html [--demo]` 生成单文件滑卡判决台；4:3 卡三级信息层级：①大号一审建议条（留绿/删红/争议琥珀，附判决理由）②笔记总结（讲什么/有什么用）③标题元信息+全文备查；一次一张卡：左键/左滑=删、右键/右滑=留、上键/上滑=返回上一条并清除其判决重判；另有一键采纳一审、中断自动保存（刷新从首张未判继续），审完导出 `verdict_<批次>_final.json` 交给助手
- **判决台只产生判决文件，不执行删除**：拿到 verdict JSON 后仍走第 5 节 dry-run→确认→apply；pending 篇一律不动，demo 批次仅演练；ID 若已不在库中 dry-run 自然拦截。主审核交互（键鼠优先，2026-09-28 定）：键盘 ←/1 删、→/2 留、↑/3 撤销上一条，判定后自动跳下一条；底部大号圆形按钮（删/撤销/留）供触屏或不愿用键盘时点击；卡片可直接左右/上下拖拽判定；顶部进度条与计数随判随更新。点顶部「总览目录」弹出全量清单（标题+当前判定徽标），可按 全部/待判/判留/判删 筛选，点任意条目直接跳过去重判，Esc 关闭。判决自动存本机浏览器。注：摄像头体感（手动滑动/头动）因识别不稳已不接线，相关代码保留。现有两个**可选**增强通道（互不影响，键鼠始终可用）：
- **🎤 语音控制**：点击开启后说「**保留 / 删除 / 撤销**」（也认 留/删/撤回/上一个 等同义说法）。Chrome Web Speech API，zh-CN，连续识别 + 500ms 防抖，总览打开时不响应；麦克风未授权或网络不通则关闭/提示并退回键鼠。**数字（1/2/3）不作为语音指令**（2026-09-28 用户明确要求只用三种中文命令）。国内网络下 Google 语音服务常不可用，能否用取决于网络。
- **🖐 手指识别**：点「🖐 手指识别」开摄像头（MediaPipe HandLandmarker，视频不出本机，预览窗可拖动缩放）。举手比手势：**握拳=暂停/继续（切换）、1 指=留、2 指=删、3 指=撤销**。判定用「伸展手指数」（指尖离腕 > 指中节离腕×1.15，不数拇指），需**连续 8 帧结果一致（约 0.25s）**才生效，两次判定间隔 ≥700ms，且同一手势须换手势或手离开画面 0.5s 后才能再触发（防误判/防连击）。暂停时手势/语音/键鼠判决输入全部冻结，顶部显示「⏸ 已暂停」，再握拳或点提示条继续。预览窗内实时显示"当前几指 + 稳定帧数"，无反应时先看这里。
- **注意数字映射不一致**：键盘是 `←/1删 →/2留 ↑/3撤`，而手指是 `1指留 2指删 3指撤`（1/2 正好相反）。两者别混着记，以各自提示为准。
样例：`_系统数据/review_batch_demo.tsv` + 驾驶舱《二审判决台.html》。
**交卷全自动（2026-09-29 用户重申，据此改造）**：最后一张卡判完，判决台**自动保存**为 `verdict_<批次>_final.json` 并落到浏览器下载目录，用户不需要点任何按钮（判决指纹变了才再交一次，撤销重判会自动再交；仍可手点「导出判决 JSON」兜底）。
Agent 侧的自监督：启动 `scripts/watch_verdict.py --batch <批次> --interval 300 --max-minutes 720`（**每 5 分钟查一次**下载目录，日志 `logs/watch_verdict_<批次>.log`，超时自退即自动解绑），命中即校验 → 移动（不是复制）到规定路径 `_系统数据/verdicts/` → **自动跑 `scripts/apply_verdict.py --batch <批次>` 出 dry-run 预览**并保存到 `00_项目驾驶舱_可视化中心/二审执行_<批次>.md`（校验留删两侧"台账/飞书映射/全文"三件是否齐全、扫四类孤儿、按判据编号列出判留/判删、标出走「笔记可删·案例可留」的争议篇）。
**唯一还留人工的一步是真删**：§5 明令 dry-run→确认→apply，所以 `apply_verdict.py` 默认只读，加 `--apply` 才动四处（争议篇先自动提炼进 `保留_案例与方法.md` 再删原文；**按 `multi-store-sync-delete` 的 SOP：云端飞书行先删、本地后删，每批 ≤44 个 record-id、不回显 ok 立即停，不自建任何备份目录**；判留自动续接精选库编号并同步 front-matter 计数；删完当场跑 §5 终检）。用户全程只需：开 HTML → 刷卡 → 说一个"执行"。

## 3. 一审讲什么

每篇四件事：①一句话是什么 ②具体能干嘛/关键细节 ③坑（花钱、环境、时效、风险）④明确预判 + 判据编号。
与历史判例同款的笔记要主动指出（如"同款你此前已删过 N 篇"）。

## 4. 口味判据（判例实证，持续更新）

### 保留（满足任一，且有实质内容）
1. **已落地实物**：已安装/已产出成果，或用户明确要动手
2. **不过时的认知/方法论**：脱离工具版本的判断力、可复用提示词/工作流（如反向漏斗信任变现、双向钢人 Prompt、反 AI 谄媚）
3. **可迁移技术思路**：能用于 AI 内容创作 / 知识管理 / 小红书 / Vibe Coding 主线（如 Video as Code、东方海报大色域+微场景）
4. **稀缺生活/社交程序知识**："怎么办"的隐性规则，生活中很难系统学到
   - 已判留：高难手术选医生（查学会指南牵头医院、选重临床的中青年医生）
   - 已判留：商务饭局人情世故（座次/敬酒/买单）
   - 已判留：领导出差助理 SOP、出行医疗安全评估
   - 边界：**公开的显性政策信息不算**（军队文职招考科普→删：官方可查+无个人场景）；鸡汤/情绪价值不算；
     **保命/应急类算**（2026-10-10 判例：车内降温除味"是保命的技巧"→留）——意外场景立刻要用、来不及搜
5. **顶级 AI 公司应用 AI 的方法论理念**（2026-10-10 判例）：Claude Code / OpenAI 等公司"怎么用 AI"的理念与做法值得学——

   长期经验沉淀的合集型内容→留；**单点探店/种草**→删。分界是"厚度"：十年一遭的整理 vs 一家店/一道菜

   专业的亲密关系/家庭心理学认知→留；**多元思想/人生选择访谈**（赵鼎新）同批判留——三观类深度思考→留
8. **可改造基座型资产**（2026-10-11 判例：video-shotcraft 106 镜头配方 Skill 留）：“可以基于他的东西来
   修改”——能当他项目基座/素材库的工具与模板→留。与判据 8（已有更强替代→删）的分界：
   Remotion **官方 skill** 是替代关系→删旧教程；Remotion **之上的配方 Skill** 是互补基座→留
9. **赚钱/变现方法类**（2026-10-11 判例：公众号副业收入分享留、AI 壁纸变现留）：他原话"要多多学习赚钱

    单个笔记可删，但作者思路可学 → **保留"人"**。筛选升级到作者级：他要的是"思考问题的思路 + 从哪学的

    他主动规划的未来场景（开店）的思路→留。与删除判据 10（偶然窄场景→删）的分界：
    **"我以后会做" vs "只有当我正好在做"**

### 时效分级（2026-10-11 郭老师问"保留一周/两周/一个月？"后立）
会过时但值得留的信息（平台评测、价格、政策），**按台账已有的 时效 字段分级打保质期**：
- **短期 7 天**：价格/活动/限免类
- **中期 1 个月**：平台评测/工具额度类（opus5.5 平台盘点归这档）
- **长期**：方法论/认知类（无保质期）
到期由每日管线的 **任务 C（旧信息联网时效复核）**自动检；复核失效→降档或转删。
**保质期不是"到时自动删"，是"到时自动复核"**——复核后由他或 AI 二审决定去留。

### 删除（命中即删，多为多条同时命中）
1. 会过时的情报：工具版本号、免费额度、优惠、积分、抽奖、限免活动
2. 要花钱/订阅；要重折腾环境（WSL/OAuth/命令行部署）；硬件不支持
3. 纯产品软文 / **四无**（无工具名、无步骤、无提示词、无链接，"评论区领取"类）
4. 与主线无关，且不属于第 4 条保留判据
5. 高风险：封号、实盘炒币/理财（理财引流内容已判删：指数基金、银行维权取证属低概率极端个案；

### 元规则
