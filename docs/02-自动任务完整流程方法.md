## 1. 环境准备（守护进程 + 扩展）

全流程依赖 kimi-webbridge 守护进程驱动用户真实浏览器，必须先确保它处于「扩展已连接」状态。

### 1.1 检查并启动守护进程

```powershell
& "$env:USERPROFILE\.kimi-webbridge\bin\kimi-webbridge" status
```

期望输出：`{"running":true, "extension_connected":true, ...}`。
若 `running:false` → 执行 `start`；若 PID 文件陈旧（提示 daemon may be starting or stuck）→ 删除 `daemon.pid` 后重新 `start`。

### 1.2 扩展连接异常的修复（关键）

> **症状**：`extension_connected:false`，HTTP API 返回 `502 Bad Gateway`。
> **根因**：Kimi WebBridge 浏览器扩展（Web Store 官方 ID `fldmhceldgbpfpkbgopacenieobmligc`）未安装/被移除/Chrome 崩溃后未重建连接。守护进程只认官方扩展 ID，开发者模式手动加载的解压版（ID 形如 `mbonag...`）无法被识别。

1. 确认扩展已装：Chrome → `chrome://extensions/` 应看到官方版 Kimi WebBridge；若只有解压版或没有，则需处理。
2. 若官方版丢失：先移除开发者模式的解压版（否则 Web Store 会报「This item is already installed」冲突），再打开 `https://chromewebstore.google.com/detail/kimi-webbridge/fldmhceldgbpfpkbgopacenieobmligc` 点「添加至 Chrome」重装。
3. 装好后触发一次激活：打开 `chrome-extension://fldmhceldgbpfpkbgopacenieobmligc/sidepanel.html`（或点工具栏扩展图标），让扩展 service worker 重建连接。
4. 回到 `status` 确认 `extension_connected:true` 后再继续。

> ✓ 判断连接是否可用：调用一次 evaluate 返回真实结果、或一次性 navigate 成功返回 `tabId`，即代表链路通了。

## 2. 拉取最新点赞列表

目标：一次 evaluate 拿全「赞过」页全部卡片，禁止逐条进详情页。

### 2.1 导航到赞过页

```json
{"action":"navigate","args":{"url":"https://www.xiaohongshu.com/user/profile/<XHS_USER_ID>?tab=liked"},"session":"xhs"}
```

返回 `{"success":true,"tabId":...}`。等待 6~8 秒让页面渲染完。

### 2.2 一次性批量提取（核心 JS）

```javascript
(() => {
  const uid = /\/user\/profile\/([^/?]+)/.exec(location.pathname)?.[1] || '';
  const items = [];
  const cards = document.querySelectorAll('section.note-item, div.note-item');
  cards.forEach((c) => {
    const a = c.querySelector('a.cover') || c.querySelector('a');
    const href = a ? (a.getAttribute('href') || '') : '';
    if (!href) return;
    let full = href;
    if (href.startsWith('/user')) full = 'https://www.xiaohongshu.com' + href;
    else if (!href.startsWith('http')) {
      const q = href.includes('xsec_token') ? (href.split('?')[1] || '') : '';
      full = 'https://www.xiaohongshu.com/user/profile/' + uid + '/'
             + href.split('/').pop().split('?')[0] + (q ? '?' + q : '');
    }
    // 必须取 note_id 对应字段，勿取到 uid
    const idm = full.match(/\/([0-9a-f]{24})(?:\?|$)/);
    if (!idm) return;
    const id = idm[1];
    const title = (c.querySelector('.title, a.title')?.innerText || '').trim();
    const author = (c.querySelector('.author, .name, .author-wrapper .name')?.innerText || '').trim();
    const like = (c.querySelector('.like-wrapper .count, .count, .like')?.innerText || '').trim();
    const isVideo = !!c.querySelector('.play-icon, [class*="play"], [class*="video"], .duration, [class*="time"]');
    const type = isVideo ? '视频' : (c.innerText.includes('视频') ? '视频' : '笔记');
    items.push({ id, href: full, title, author, like, type });
  });
  return JSON.stringify({ count: items.length, url: location.href, items });
})()
```

### 2.3 注意陷阱

- **note_id 提取**：赞过页链接形如 `/user/profile/{uid}/{note_id}?xsec_token=...`，uid 和 note_id 都是 24 位 hex。若用 `/([0-9a-f]{24})/` 会**误匹配到 uid**。必须匹配「最后一个 24-hex 位于路径末端」即 `\/([0-9a-f]{24})(?:\?|$)`。
- **必须带 xsec_token**：纯 `/explore/{id}` 链接被点点总结时返回 `NOT_FOUND`。完整链接格式 `/user/profile/{uid}/{note_id}?xsec_token=XXX&xsec_source=pc_user`。
- 一次拿全标题、作者、点赞数、类型；败于逐条进详情页（慢且触发反爬 404）。
- **懒加载与滚动**：小红书点赞页采用滚动懒加载。页面只渲染部分时，通过 evaluate 执行滚动并等待 1.5 秒：
  ```javascript
  window.scrollTo({ top: document.documentElement.scrollHeight, behavior: 'smooth' });
  ```
  等待卡片 DOM 挂载后再次 evaluate 补拉，直到无新卡片或达上限（约 30~40 条）。

## 4. 比对找出新增

以链接中的 note_id 为主键判断新增，写一个 Python 脚本完成提取与比对。

### 4.1 正确提取 note_id

```python
import re
UID = "<XHS_USER_ID>"

def extract_note_id(link):
    m = re.search(r"/explore/([0-9a-f]{24})", link)          # explore 格式
    if m: return m.group(1)
    ids = re.findall(r"([0-9a-f]{24})", link)                 # profile 格式
    for i in ids:
        if i != UID: return i                                  # 跳过 uid，取 note_id
    return None
```

> ✓ 判定规则：
> - 已存在于表格 → 非新增
> - 链接/note_id 不在表格 → 新增
> - 同一链接只处理一次（取消赞重赞、标题改动都不重复）

> ⚠ 若比对后「新增 0 条」：跳过总结与表格更新，直接走**第 7 步清理**，回复只写「本次无新增」。这是常态，多数时候当日无新点赞。

## 5. 点点逐条总结

全程只用一个「点点」对话标签页，不每条新开；用 kimi-webbridge 直接 evaluate。

### 5.1 打开并复用点点对话

若还没有点点对话标签页，直接通过 kimi-webbridge 调用导航打开独立入口：
```json
{"action":"navigate","args":{"url":"https://www.xiaohongshu.com/ai_chat"},"session":"xhs"}
```
等待 3~5 秒加载完成，记住其 tab 索引；后续所有点赞笔记的总结均在该页面连续提问复用，切勿每条新开标签页。

### 5.2 逐条注入提问并获取回答

构造提问：`请总结这个小红书视频的内容，给出内容概要、主题分类、关键信息点：{完整xsec链接}`

### 5.3 注入文字（type 会丢字，必须 JS setter）

```javascript
(() => {
  const ta = [...document.querySelectorAll('textarea')].find(t => t.offsetParent !== null);
  if (!ta) return 'no ta';
  ta.focus();
  const setter = Object.getOwnPropertyDescriptor(window.HTMLTextAreaElement.prototype, 'value').set;
  setter.call(ta, PROMPT);
  ta.dispatchEvent(new InputEvent('input', { bubbles: true, inputType: 'insertText', data: PROMPT }));
  return 'injected:' + ta.value.length;
})()
```

PROMPT 用 JSON 字符串内联；备选方案 `document.execCommand('insertText', false, msg)`。

### 5.4 发送（用 JS .click()）

```javascript
document.querySelector('div.submit-button-wrapper')?.click();
```

### 5.5 等待并取答案（平稳态窗口轮询，防流式截断）

```javascript
(() => {
  const ms = [...document.querySelectorAll('.ai-message')];
  const last = ms[ms.length - 1];
  return last ? (last.innerText || '').trim() : '';
})()
```

> ⚠ **防流式半截截断算法**（见 `scripts/xhs_dd_poll.py`）：
> 点点为流式打字机输出，不能只看 `.ai-message` 数量 `+1` 就立即取值。必须进行**双重平稳态检测**：
> 1. **过滤占位符**：若文本含“问题分析中”、“思考中”、“正在总结”且长度 < 20 字，视为未完成；
> 2. **稳定态判定**：每隔 2 秒轮询一次，当内容长度 > 30 字且**连续 2 次轮询文本内容完全一致**（`stable >= 2`），方可判定为流式输出结束，返回完整分析。

### 5.6 存档原始回复

每条原始回复（含【用户提问】+【点点回复】）存为 `D:\workbuddy 工作空间\点点分析结果\raw_YYYYMMDD\raw_{序号}_{note_id}.txt`。

## 6. 生成报告 + 写回飞书

### 6.1 生成汇总报告


### 6.2 批量写入飞书（一次写完）

用 `base +record-batch-create` 一次性写入全部新增，字段必须与飞书 Base 列名严格对应：

```python
fields = ["标题", "序号", "作者", "点赞数", "链接", "内容类型", "分类", "点点总结", "主题标签", "存档文件"]
rows = []
for r in results:
    rows.append([
        r["title"],
        r["seq"],
        r["author"],
        r["like"],
        r["href"],
        r["type"],                  # 如 "视频" 或 "笔记"
        "小红书点赞分析",            # 固定分类
        r["summary"],
        r["tags"],
        os.path.basename(r["raw_file"])
    ])
payload = {"fields": fields, "rows": rows}
```

### 6.3 JSON 转义与写入执行（推荐存临时文件传递）

```python
import subprocess, json

payload_path = "./_lark_payload_temp.json"
with open(payload_path, "w", encoding="utf-8") as f:
    json.dump(payload, f, ensure_ascii=False)

cmd = [
    lark_bin, "base", "+record-batch-create",
    "--base-token", "<FEISHU_BASE_TOKEN>",
    "--table-id", "<FEISHU_TABLE_ID>",
    "--json", f"@{payload_path}",
    "--as", "user", "--format", "json"
]
subprocess.run(cmd, capture_output=True, text=True, encoding="utf-8")
```

> ⚠ **避坑要点**：
> 1. 绝对不要在 Windows PowerShell 命令行中直接拼接长 JSON 字符串，极易被引号拆分破坏；
> 2. 使用 `@./_lark_payload_temp.json` 语法将 JSON 文件直接交给 `lark-cli` 解析。

## 8. 常见坑与对策

| 坑 | 对策 |
|---|---|
| 点点输入框 type 不保留文字 | JS 原生 setter + input 事件注入 |
| 发送按钮点错（点到附件） | 定位 `div.submit-button-wrapper` 用 JS `.click()` |
| 直接访问笔记 URL 反爬 404 / 点点 NOT_FOUND | 从「赞过」页卡片取带 xsec_token 的完整链接 |
| note_id 被误取成 uid | 用 `\/([0-9a-f]{24})(?:\?|$)` 匹配路径末尾的 note_id，跳过 uid |
| kimi-webbridge 扩展断连（502 / extension_connected:false） | 重装 Web Store 官方版扩展（ID fldmhcel...）并激活 sidepanel 触发连接 |
| lark-cli `--format ndjson` 报错 | 用 `--format json` |
| lark-cli 命令找不到 | 用真实绝对路径 `C:\Users\<USER_NAME>\AppData\Roaming\TRAE SOLO CN\...\lark-cli.cmd` |
| PowerShell 传 JSON 参数被拆分 | 用 Python subprocess 调用 lark-cli |
| 逐帧快照慢 | 全程走 kimi-webbridge HTTP API 直接 evaluate |
| 固定长等待浪费 | 1~2s 短增量轮询 `.ai-message` 数量变化 |
| 每视频开新标签页浪费 | 复用同一点点对话标签页 |
