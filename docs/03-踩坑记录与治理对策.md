# 踩坑记录与治理对策 · 小红书点赞分析

> **定位**：在实际开发与日常自动化调度中遇到的深水区坑点、技术根因及最终治理方案。  
> **更新时间**：2026-09-22

---

## 1. 反爬与链接有效性

### 1.1 `xsec_token` 缺失导致点点报 `NOT_FOUND`
* **现象**：将短链接形如 `https://www.xiaohongshu.com/explore/{note_id}` 喂给点点，点点回复“找不到该笔记”或 `NOT_FOUND`。
* **根因**：小红书近期加强了 Web 端内容防爬。所有未携带 `xsec_token` 和 `xsec_source` 的请求在内嵌 AI 解析器中会被判定为无授权访问或匿名爬虫而被拦截。
* **对策**：在个人主页“赞过”列表提取卡片时，直接提取完整的 `href`（形如 `/user/profile/{uid}/{note_id}?xsec_token=...&xsec_source=pc_user`），保留完整的安全校验凭证。

### 1.2 逐条进入详情页导致 404 / 滑动验证码
* **现象**：若脚本模拟人工点击卡片逐条进入详情页获取正文，连续访问 3~5 条后即出现 404 或弹出滑块验证码，自动化流程彻底阻断。
* **根因**：小红书对 Web 端的详情页高频导航有极高风险等级的风控检测。
* **对策**：采用“在点赞页单次 evaluate 提取所有可见卡片”策略，笔记的封面、标题、作者、类型、点赞量全部从卡片 DOM 解析，完全绕过详情页访问。

## 2. 浏览器 DOM 交互与事件受控机制

### 2.1 React/Vue 受控文本框 `value` 注入无效
* **现象**：在点点会话框使用 `textarea.value = "..."` 赋值后，点击发送按钮，发送的是空内容或直接抛错。
* **根因**：点点输入框属于现代前端框架的受控组件（Controlled Component），仅修改 DOM 属性不会触发 React/Vue 的内部状态（fiber/state）变更。
* **对策**：通过原型链拦截器的 setter 强制触发底层原生更新，并显式分发冒泡的 `InputEvent`：
  ```javascript
  const setter = Object.getOwnPropertyDescriptor(window.HTMLTextAreaElement.prototype, 'value').set;
  setter.call(textarea, text);
  textarea.dispatchEvent(new InputEvent('input', { bubbles: true, inputType: 'insertText', data: text }));
  ```

### 2.2 大模型打字机流式输出（Streaming）截断
* **现象**：监测到页面新增 `.ai-message` 元素后立即取文本，抓取到的回复经常只有前 5~10 个字，甚至只有“正在分析中...”。
* **根因**：AI 会话页面的 DOM 节点在建立连接的第一时间即挂载入树（Streaming 初始阶段），随后字符增量推入。
* **对策**：设计平稳态滑动窗口算法（Stable Window Polling）：
  1. 过滤“正在总结”、“问题分析中”等过渡状态词；
  2. 轮询间隔设定为 2 秒，当获取文本长度 > 30 且连续两次轮询的内容完全相同时，才判定为生成完毕。

## 3. 跨系统调用与命令行生态

### 3.1 Windows PowerShell 长 JSON 二次拆分与引号转义失效
* **现象**：在 PowerShell 终端执行 `lark-cli base +record-batch-create --json "{...}"` 时，报参数解析错误或 JSON 语法错误。
* **根因**：PowerShell 对外部 CLI 传参时会对双引号 `"` 和特殊换行符进行隐式解包重组。
* **对策**：
  1. 避免使用 PowerShell 直接拼装 JSON 字符串；
  2. 使用 Python 的 `subprocess` 模块，将 payload 保存为临时文件，通过 `--json @filepath` 方式传递给 `lark-cli`。

### 3.2 飞书多维表格列名映射与类型校验
* **现象**：写入多维表格报 400 Bad Request。
* **根因**：`+record-batch-create` 要求的格式为 `{"fields": [...], "rows": [[...], ...]}`，其中 `fields` 的数组必须与 Base 中列名称严格匹配；序号字段需为数字，多选标签需为字符串数组。
* **对策**：在 Python 写入模块中建立严格的 Schema 校验层，对缺省字段补充默认值（例如类型缺省为 `["视频"]`）。

## 4. 守护进程与扩展连接

### 4.1 kimi-webbridge 返回 502 Bad Gateway
* **现象**：执行 evaluate 时 HTTP API 报错 `502 Bad Gateway`，`kimi-webbridge status` 提示 `extension_connected: false`。
* **根因**：
  1. Chrome 扩展被系统休眠/挂起或 Chrome 崩溃后未重连；
  2. 误装了开发者解压版扩展（ID 冲突或非官方 ID），守护进程只认 Chrome Web Store 官方扩展 ID `fldmhceldgbpfpkbgopacenieobmligc`。
* **对策**：
  1. 移除开发者模式未打包扩展；
  2. 重装官方 Web Store 扩展，并打开侧边栏 `sidepanel.html` 主动激发连接。
